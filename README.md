# xitdb-rs

[![crates.io](https://img.shields.io/crates/v/xitdb.svg)](https://crates.io/crates/xitdb)
[![docs.rs](https://img.shields.io/docsrs/xitdb.svg)](https://docs.rs/xitdb)
[![CI](https://github.com/ToyVo/xitdb-rs/actions/workflows/ci.yml/badge.svg)](https://github.com/ToyVo/xitdb-rs/actions/workflows/ci.yml)

An immutable, embedded database in Rust — a port of
[xit-vcs/xitdb](https://github.com/xit-vcs/xitdb) (Zig), following
[xitdb-go](https://github.com/xit-vcs/xitdb-go) as the idiomatic-port model.

Each transaction efficiently creates a new copy of the database while past
copies stay readable and revertible. There is no query engine: you nest
in-memory-like collections (primarily `ArrayList` and `HashMap`) on disk
or in memory.

- Single-file or purely in-memory use; runs embedded as a library.
- Zero dependencies (SHA-1 and OS randomness are vendored in-tree).
- Byte-compatible files with the Zig, Go, TypeScript, Java, and Clojure
  implementations when opened with the same hash.
- Reads never block writes; each thread uses its own `Database`.

## Quickstart

```rust
use xitdb::arraylist::WriteArrayList;
use xitdb::core::MemoryCore;
use xitdb::cursor::Writeable;
use xitdb::database::{Database, InitOpts};
use xitdb::hasher::Sha1Hasher;
use xitdb::hashmap::{HashMap, WriteHashMap};

let db = Database::open(
    MemoryCore::new(),
    Sha1Hasher,
    InitOpts { hash_id: None, file_id: None, fsync: false },
)?;

// The top-level ArrayList is the history: each item is a moment in time.
db.run_context(|w| {
    let history = WriteArrayList::new_write(w)?;
    history.append_context(Writeable::None, |mc| {
        let moment = WriteHashMap::new_write(mc)?;
        moment.put("hello", Writeable::Bytes(b"world".to_vec()))?;
        Ok(())
    })
})?;

let w = db.root_cursor();
let history = WriteArrayList::new_write(&w)?;
let moment = HashMap::new(history.get(0)?.unwrap())?;
let value = moment.get("hello")?.unwrap().read_bytes_alloc()?;
assert_eq!(value, b"world");
```

## Collections

| Type | Notes |
| --- | --- |
| `HashMap` / `HashSet` | Hash-trie maps, string/`bytes`/hash keys |
| `CountedHashMap` / `CountedHashSet` | As above, with a maintained count |
| `ArrayList` | Growable array, negative indexing |
| `LinkedArrayList` | B-tree list: slice, concat, insert, remove |
| `SortedMap` / `SortedSet` | B-tree index for ordering, pagination, type-ahead |

Scalars are `Uint`/`Int`/`Float`/`Bytes`, with optional 2-byte format tags
on byte arrays. See the [Zig README](https://github.com/xit-vcs/xitdb) for
the full narrative (cloning with `freeze`, secondary indexes, compaction,
replication) — the concepts and file layout are identical here.

## Backends

`MemoryCore`, `FileCore`, and `BufferedFileCore` (recommended for files).
Writes must be serialized by the caller with an exclusive file lock;
reads need none. See the [crate docs](https://docs.rs/xitdb) for details.

## Compatibility

`tests/fixtures/` holds databases written by other implementations
(`test.db` vendored from xitdb-go, `go-golden.db` generated by
`scripts/gen-fixtures.sh`), and `tests/compat.rs` proves they read
identically here. The same script has Go read back Rust-written files.
